# Desain v1: Dashboard Sisa Kas ATM

Implementasi [PRD v1](../prd/v1-dashboard-kas.md). Acceptance criteria (AC) di PRD tetap sumber kebenaran. Dokumen ini menjelaskan cara AC itu dipenuhi.

## Ringkasan

Satu halaman (`/`) yang membaca tabel `atms` dari Supabase setiap kali dibuka, menghitung status per ATM, lalu menampilkan ringkasan dan daftar terurut. Semua aturan bisnis ada di fungsi murni `lib/` dan diuji dengan Vitest. Halaman hanya membaca. Tidak ada jalur tulis di v1.

## Alur request

```
GET /?region=BDG
 └─ app/page.tsx  Home (shell statis: judul, petunjuk, footer)
     └─ <Suspense fallback="Memuat data sisa kas…">
         └─ Dashboard (dirender saat request)
             1. parseRegion(searchParams.region)   → "BDG" atau null (Semua region)
             2. getAtms()                          → lib/atms-data.ts, query Supabase dengan anon key
                ├─ gagal → LoadError: "Data sisa kas gagal dimuat. Coba muat ulang."
                └─ berhasil ↓
             3. buildDashboard(atms, region)       → rows (terfilter + terurut), summary, emptyMessage
             4. render RegionFilter, waktu muat, StatusSummary, AtmTable atau pesan kosong
```

## Keputusan

### Status dihitung dengan integer, kapasitas 0 dicek lebih dulu

`getStatus` mengembalikan Kritis untuk kapasitas 0 (AC3), lalu membandingkan `sisaKas × 100 < 20 × kapasitas` dan `< 40 × kapasitas`. Tidak ada pembagian, jadi tidak ada error pembulatan desimal. Untuk nominal ratusan juta, hasil perkalian sekitar 10¹⁰, jauh di bawah batas integer aman JavaScript (≈ 9 × 10¹⁵).

Angka 20 dan 40 hanya ditulis di `THRESHOLDS` (PRD P2: ambang per ATM nanti cukup diubah di satu tempat). Garis ambang di level kas juga membaca konstanta ini.

### Persentase tampil dibulatkan ke bawah

`getDisplayPercent` memakai `Math.floor`, jadi 19,99…% tampil 19% dan cocok dengan badge Kritis (AC10). Sisa kas di atas kapasitas tampil apa adanya, misalnya 105% dan Aman (keputusan untuk PRD Q2).

### Urutan memakai rasio sebelum dibulatkan

`sortAtms` mengurutkan dengan `sisaKas / kapasitas` (kapasitas 0 dianggap 0), lalu ID dengan perbandingan string biasa untuk persentase seri (AC4, AC11). Perbandingan silang `a.sisa × b.kapasitas` sengaja tidak dipakai, karena hasilnya bisa mencapai 4 × 10¹⁶ dan melewati batas integer aman. Pecahan yang nilainya sama persis menghasilkan angka desimal yang sama persis, jadi seri tetap terdeteksi. `localeCompare` tidak dipakai karena hasilnya bergantung pada locale.

### Ambil semua baris, filter di `lib/`

Tabel hanya berisi 12 ATM, jadi `getAtms()` mengambil semua baris dan `buildDashboard` yang memfilter. Manfaatnya:

- Filter, urutan, dan ringkasan teruji tanpa database (AC5, AC6, AC13).
- Daftar dan ringkasan dihitung dari array yang sama, jadi jumlahnya pasti cocok (AC6).
- "Belum ada data ATM." (tabel kosong) bisa dibedakan dari "Tidak ada ATM di region ini." (filter tanpa hasil) (P1-1).

Kalau jumlah ATM sudah ribuan, filter region perlu dipindah ke query (`.eq("region", …)`).

### Data dibaca saat request (AC9)

`next.config.ts` mengaktifkan `cacheComponents`. Di mode ini `export const dynamic = "force-dynamic"` dan `revalidate` tidak dipakai lagi. Caranya:

- Komponen `Dashboard` membaca `searchParams` dan memanggil Supabase di dalam `<Suspense>`. Shell halaman di-prerender saat build, sedangkan isi `<Suspense>` dirender setiap request. Output build menandai `/` sebagai **◐ Partial Prerender**.
- Tidak ada `"use cache"` di jalur data.
- `getAtms()` memanggil `await connection()` sebelum query. Tanpa ini, Next juga memulai query di render prerender saat request lalu membatalkannya, sehingga setiap kunjungan menulis error palsu ("fetch() rejects when the prerender is complete") ke log server. Setelah ditambahkan, log palsu itu hilang. Hasil ukur dengan mock: satu kunjungan tetap satu query, sebelum maupun sesudah perubahan ini.
  - Docs Next menyarankan `io()` untuk kerja yang boleh di-prefetch dan di-cache. Di sini `connection()` sengaja dipilih, karena sisa kas harus diambil untuk request user sungguhan.
  - Efek sampingnya, prefetch tidak membawa data ATM. Itu memang diinginkan, karena data hasil prefetch bisa sudah usang saat diklik.
- `new Date()` untuk "Data per …" dipanggil setelah data diambil, jadi waktunya selalu waktu request.

### Error dikembalikan sebagai nilai (P1-2)

`getAtms()` tidak pernah melempar error. Env var kosong, error Supabase, timeout 8 detik, atau nominal yang bukan integer aman ≥ 0 menghasilkan `{ ok: false }`. Halaman lalu menampilkan "Data sisa kas gagal dimuat. Coba muat ulang." tanpa ringkasan, supaya tidak terlihat seolah semua ATM aman.

- Detail penyebab hanya ditulis ke log server dengan awalan `[atms]`. URL dan kunci Supabase tidak pernah dicatat atau ditampilkan.
- Error yang di-throw dari Server Component diganti pesan generik oleh Next di produksi, jadi pesan PRD hanya bisa dijamin lewat nilai kembalian.
- Tombol "Muat ulang" adalah `<a>` biasa ke URL yang sama (filter tetap), jadi browser memuat ulang halaman sepenuhnya.

### Env var dan kunci

- `NEXT_PUBLIC_SUPABASE_URL` dan `NEXT_PUBLIC_SUPABASE_ANON_KEY`, sama dengan nama di RUNBOOK. Dibaca di dalam `getAtms()` (server), tidak di level modul, jadi build tetap lolos tanpa env var.
- Next menanam nilai `NEXT_PUBLIC_*` ke hasil build, termasuk di code server. Akibatnya, mengubah env var butuh redeploy. Perubahan data tidak.
- v1 memakai anon key, bukan service role key. Query tunduk pada RLS, jadi kunci yang terlihat di browser pun tidak bisa menulis data.

### Filter di URL (P1-3)

Chip filter adalah `<Link href="/?region=BDG">`, tanpa JavaScript di sisi klien. `parseRegion` hanya menerima `JKT-SEL`, `JKT-PUS`, dan `BDG` (huruf besar). Nilai lain dianggap Semua region. Jika parameter muncul dua kali, nilai pertama yang dipakai.

### Waktu muat dalam WIB (P1-4)

`formatDataTime` menggeser waktu 7 jam lalu membaca komponen UTC, dengan nama bulan Indonesia dari daftar tetap. WIB tidak memakai daylight saving, jadi hasilnya sama di server mana pun, tidak bergantung pada zona waktu atau data locale server.

## Database

### Tabel `atms`

| Kolom | Tipe | Catatan |
|---|---|---|
| `id` | `text` primary key | Stabil, misalnya `ATM-BDG-01` (PRD P2, dipakai `refill_requests.atm_id` di v2) |
| `lokasi` | `text` not null | Nama fiktif, tanpa nama bank |
| `region` | `text` not null | Kolom terpisah, supaya RLS bisa diperketat per region nanti (PRD P2) |
| `sisa_kas` | `bigint` not null, CHECK ≥ 0 | Integer rupiah |
| `kapasitas` | `bigint` not null, CHECK ≥ 0 | Integer rupiah. 0 diizinkan dan tampil Kritis (AC3) |

### Keputusan untuk pertanyaan terbuka PRD

Diputuskan 22 Okt 2026 saat implementasi:

- **Q1**: ya, CHECK `sisa_kas >= 0` dan `kapasitas >= 0`.
- **Q2**: sisa kas di atas kapasitas tampil apa adanya (misalnya 105%) dan berstatus Aman, tanpa tanda khusus. Diuji di `lib/atm.test.ts`. Kalau nanti PRD memutuskan lain, ubah test itu lebih dulu.

### RLS (AC7)

- `enable row level security`, ditambah satu policy `SELECT` untuk role `anon` dan `authenticated` dengan `using (true)`.
- Tidak ada policy `INSERT`, `UPDATE`, atau `DELETE`, jadi RLS menolak semua penulisan.
- Hak tabel `anon` dan `authenticated` dicabut lalu diberi `SELECT` saja. Penolakan tulis jadi tidak hanya bergantung pada RLS. `TRUNCATE`, misalnya, tidak diperiksa oleh RLS.

### Seed (AC14)

| Region | Kritis | Waspada | Aman |
|---|---|---|---|
| `JKT-SEL` | JKS-01 (15%) | JKS-03 (30%) | JKS-02 (45%), JKS-04 (94%) |
| `JKT-PUS` | JKP-02 (10%) | JKP-03 (39%), JKP-04 (tepat 20%) | JKP-01 (tepat 40%) |
| `BDG` | BDG-01 (19,8%), BDG-02 (19,2%) | BDG-03 (30%) | BDG-04 (80%) |

Data ini sengaja memuat kasus yang bisa dicek mata saat demo:

- BDG-02 (19,2%) tampil di atas BDG-01 (19,8%) walaupun keduanya tampil 19% (AC4).
- BDG-03 dan JKS-03 sama-sama tepat 30%, jadi diurutkan berdasarkan ID (AC11).
- JKP-04 tepat 20% (Waspada) dan JKP-01 tepat 40% (Aman) (AC1, AC2).

`lib/seed.test.ts` membaca file seed dan memastikan isinya memenuhi AC14. Karena itu, pertahankan format satu ATM per baris di file seed.

Seed memakai `on conflict (id) do nothing`. Menjalankannya ulang tidak menimpa angka yang sudah diubah di Table Editor. Untuk kembali ke angka awal, hapus barisnya dulu.

## Verifikasi setelah migrasi diterapkan

Migrasi **belum diterapkan** karena MCP Supabase belum login.

### Menerapkan migrasi

Terapkan berurutan: `create_atms` lalu `seed_atms`. Kalau memakai MCP `apply_migration`, Supabase memberi nomor versi sendiri, yang tidak harus sama dengan nama file di repo. Setelah itu jalankan advisor keamanan Supabase (`get_advisors`).

### AC7: anon key hanya bisa SELECT

Di SQL editor:

```sql
-- RLS aktif: relrowsecurity = true
select relrowsecurity from pg_class where oid = 'public.atms'::regclass;

-- Hak anon: hanya SELECT
select privilege_type from information_schema.role_table_grants
where table_schema = 'public' and table_name = 'atms' and grantee = 'anon';

-- Policy: satu baris, cmd = SELECT, roles = {anon,authenticated}
select policyname, cmd, roles from pg_policies where schemaname = 'public' and tablename = 'atms';
```

Lewat REST API dengan anon key:

```bash
URL=...   # NEXT_PUBLIC_SUPABASE_URL
KEY=...   # NEXT_PUBLIC_SUPABASE_ANON_KEY
H=(-H "apikey: $KEY" -H "Content-Type: application/json")

curl "${H[@]}" "$URL/rest/v1/atms?select=id"                                      # 200, 12 baris
curl "${H[@]}" -X POST "$URL/rest/v1/atms" \
  -d '{"id":"ATM-UJI-01","lokasi":"Uji","region":"BDG","sisa_kas":1,"kapasitas":1}'  # ditolak: permission denied
curl "${H[@]}" -X PATCH "$URL/rest/v1/atms?id=eq.ATM-BDG-01" -d '{"sisa_kas":0}'  # ditolak: permission denied
curl "${H[@]}" -X DELETE "$URL/rest/v1/atms?id=eq.ATM-BDG-01"                    # ditolak: permission denied
```

Untuk anon key format lama (JWT), tambahkan juga `-H "Authorization: Bearer $KEY"`. Setelah itu, pastikan dengan `select` bahwa ATM-BDG-01 tidak berubah.

### AC9: perubahan data terlihat tanpa redeploy

1. Buka URL produksi dan catat sisa kas satu ATM.
2. Ubah `sisa_kas` ATM itu di Supabase Table Editor.
3. Refresh URL produksi. Angka, persentase, status, dan "Data per …" harus ikut berubah, tanpa redeploy.

## Risiko dan langkah berikutnya

- **v2 butuh jalur tulis.** `refill_requests` ditulis dari server action. Anon key tidak punya hak tulis, jadi v2 perlu client server-only terpisah (service role atau secret key, tanpa prefix `NEXT_PUBLIC_`) atau policy tulis yang sempit. Tabel `atms` tetap baca saja.
- **Timeout 8 detik.** Supabase yang lambat menampilkan error, dan refresh biasanya berhasil. Project free tier yang di-pause harus di-restore manual di dashboard Supabase.
- **Perpindahan filter.** Saat chip diklik, daftar lama tetap terlihat sampai data region baru tiba (biasanya kurang dari 1 detik). Indikator loading per klik bisa ditambahkan nanti dengan komponen klien.
- **Skala.** Filter region dipindah ke query kalau jumlah ATM sudah besar (lihat bagian Ambil semua baris).
